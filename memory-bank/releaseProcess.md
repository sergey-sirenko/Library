# Выпуск новой версии

Этот процесс выполняется только по отдельной явной команде пользователя.
Репозиторий: `https://github.com/sergey-sirenko/Library`, основная ветка: `main`.

## Подготовка

1. Поднимите `APP_VERSION` в `src/uTypes.pas`.
2. Синхронизируйте README, `docs/Инструкция_установки_новой_версии.md`,
   `activeContext.md` и другие файлы Memory Bank, факты в которых изменились.
3. Завершите локальные тематические коммиты и получите чистое исходное рабочее
   дерево. Не удаляйте пользовательские или runtime-файлы ради чистоты; при
   необходимости используйте отдельное чистое рабочее дерево.

## Сборка и проверка пакета

1. Запустите `scripts/Build-Release.ps1` без `-AllowDirty`.
2. Убедитесь в `0 errors` и успехе тестов версий, JSON, SHA-256, установки и отката.
3. Проверьте архив `Library-v<версия>-win64.zip` и одноимённый файл `.sha256`.
4. В корне ZIP должны находиться только:
   - `Library.exe`;
   - `LibraryUpdater.exe`;
   - `INSTALL.md`.
5. Каталоги данных, журналы, резервные копии и другие runtime-файлы в пакет не входят.

## Публикация

1. Создайте тег `v<версия>` на проверенном коммите.
2. Отправьте согласованные коммиты ветки `main` и тег.
3. Сразу создайте стабильный GitHub Release для этого тега и приложите ZIP и
   `.sha256`.
4. Не используйте draft или prerelease: приложение читает только
   `https://api.github.com/repos/sergey-sirenko/Library/releases/latest`.
5. Программно публикуйте релиз через авторизованный GitHub CLI:
   `gh release create v<версия> dist/Library-v<версия>-win64.zip
   dist/Library-v<версия>-win64.zip.sha256 --repo sergey-sirenko/Library
   --title "Версия <версия>" --notes-file <файл с описанием> --latest`.
   Команда не должна содержать `--draft` или `--prerelease`.
6. Проверьте через `gh release view v<версия> --repo sergey-sirenko/Library
   --json tagName,isDraft,isPrerelease,isLatest,assets` и публичный API:
   - точное имя и версию тега;
   - `draft=false` и `prerelease=false`;
   - имя и размер ZIP;
   - digest вида `sha256:<хеш>`.

## Частичный сбой

Push, тег и стабильный Release образуют один процесс публикации. Если ветка или
тег уже отправлены, а корректный Release не создан, публикация не завершена.
Сообщите о сбое и продолжайте безопасное восстановление до появления проверенного
стабильного релиза либо до явной команды пользователя остановиться.
