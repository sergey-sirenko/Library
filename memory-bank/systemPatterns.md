# Системные паттерны

## Архитектура

- Данные загружаются из файлов в память при старте приложения.
- `TLibraryDB` реализует CRUD, бизнес-правила, индексы, журнал и резервные копии.
- UI построен на формах Lazarus: форма входа и главная форма с разделами.
- Сетевые функции изолированы от локального хранения и не обязательны для
  основной работы.

## Данные и целостность

- Безопасная запись: временный файл → проверка → замена → повторная проверка.
- Связи сущностей строятся по внутренним ID, а не по отображаемым значениям.
- Удаление логическое (`Deleted`, `DeletedAt`, `DeletedBy`).
- Индексы используют нормализованный ключ и ID и перестраиваются при повреждении.
- Изменение формата `.dat` или `.idx` требует явной миграции и проверки обратной
  совместимости; существующие файлы нельзя молча перезаписывать новым форматом.
- Ручное, автоматическое, страховочное и предобновленческое копирование
  используют единый полный формат: `Data`, `Covers`, EXE, updater,
  инструкции и файлы раскладки. `Logs`, `Cache`, сами `Backup`,
  временные файлы и старые EXE не копируются.
- Восстановление из UI допускает только новый полный формат и
  возвращает данные, обложки и раскладки. EXE заменяются при
  закрытой программе по вложенной `RESTORE.txt`.

## Сеть и внешние сервисы

- HTTPS выполняется через WinHTTP и системный SChannel; сторонние OpenSSL DLL не
  поставляются.
- Не использовать `fphttpclient` с `opensslsockets`: это возвращает зависимость
  от отсутствующих runtime-DLL.
- OpenRouter и GitHub Updates должны возвращать понятные ошибки и не нарушать
  локальную работу приложения.
- Ключи и реальные данные библиотеки не должны попадать в логи, документацию и Git.

## Заполнение по ISBN

- Согласованное правило: РГБ первая, затем Open Library и Google Books;
  после успеха не дополнять поля из других источников. OpenRouter здесь не использовать.
- `uRsl` разбирает только библиографические поля; `uBookText` выполняет
  локальную очистку и предупреждения; `uOpenLibrary` координирует источники и кэш.
- `uBookHttp` сохраняет cookies одной сессии и ограничивает ожидание всех запросов
  источника 15 секундами. При таймауте сетевой поток завершает запрос самостоятельно,
  не обращаясь к UI, кэшу или базе. Следующий источник получает отдельную сессию.
- Форма применяет только отмеченные поля после просмотра. Кэш используется в конце
  цепочки и повторно проверяется; исходный источник отделён от признака офлайн-загрузки.
- Внутренний интерфейс РГБ не гарантирует стабильность; неподходящий формат ответа
  приводит к предупреждению и переходу к резервному источнику.

## Обновление приложения

- Клиент читает только последний опубликованный стабильный GitHub Release.
- Версии сравниваются как `major.minor.patch`; тег может иметь префикс `v`.
- Ожидается архив `Library-v<версия>-win64.zip` с GitHub digest
  `sha256:<хеш>` и файлами `Library.exe`, `LibraryUpdater.exe`, `INSTALL.md`.
- До установки проверяются размер, SHA-256 и состав архива, затем создаётся
  резервная копия данных.
- Updater ждёт завершения приложения, сохраняет предыдущий EXE как
  `Library.exe.old`, заменяет файл, перезапускает программу и выполняет откат
  при ошибке.
- `Data`, `Covers`, `Backup` и `Logs` updater не изменяет.
