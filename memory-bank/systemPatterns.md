# Системные паттерны

## Архитектура

- Данные загружаются из файлов в память при старте приложения.
- `TLibraryDB` реализует CRUD, бизнес-правила, индексы, журнал и резервные копии.
- UI построен на формах Lazarus: форма входа и главная форма с разделами.
- Сетевые функции изолированы от локального хранения и не обязательны для
  основной работы.

## Таблицы и раскладки

- Все таблицы используют `TLibraryGrid` (`uLibraryGrid`). Свойства `Cells`,
  `Objects`, `ColWidths` и `Col` в коде форм принимают постоянные логические
  номера полей; LCL работает с физическим порядком. Номера колонок событий LCL
  переводятся через `LogicalColumn`, обращения к `Columns` — через `PhysicalColumn`.
- `SetupGrid` назначает таблице книг специальный `gridBooksSelection`, остальным —
  общий обработчик. Нельзя заменять его общим при смене схемы Books/BooksAISearch:
  специальный обработчик обновляет нижний список экземпляров выбранной книги.
- `Rows` содержит физические строки целиком: сортировка переносит их вместе
  с объектами. Нельзя переопределять виртуальные `GetCells`/`SetCells` для
  логического отображения, иначе редактор и отрисовка LCL получат другие поля.
- Раскладки хранятся в `UserLayout.cfg` с ключами `User.<ID>.<список>.ColumnsV1`;
  отчёты имеют отдельный ключ для каждого вида. Старые ключи ширин читаются
  для совместимости. Смена схемы отчёта начинается с `BeginSchema`.

## Данные и целостность

- Безопасная запись: временный файл → проверка → замена → повторная проверка.
- Связи сущностей строятся по внутренним ID, а не по отображаемым значениям.
- Удаление логическое (`Deleted`, `DeletedAt`, `DeletedBy`).
- Индексы используют нормализованный ключ и ID и перестраиваются при повреждении.
- Изменение формата `.dat` или `.idx` требует явной миграции и проверки обратной
  совместимости; существующие файлы нельзя молча перезаписывать новым форматом.
- Ручное, автоматическое, страховочное и предобновленческое копирование
  используют единый полный формат: `Data`, `Covers`, EXE, updater,
  инструкции и файлы раскладки. `Logs`, `Cache`, сами `Backup`,
  временные файлы и старые EXE не копируются.
- Восстановление из UI допускает только новый полный формат и
  возвращает данные, обложки и раскладки. EXE заменяются при
  закрытой программе по вложенной `RESTORE.txt`.

## Статистика выдач

- `uReportTotals` вычисляет суммы только колонок «Выдач», «Книг», «Читателей»,
  «Дней», «Дней просрочки» по исходному CSV отчёта, с точным Int64 и проверкой
  переполнения. Пустые значения пропускаются; ошибка числа/переполнение обозначаются
  явно. Нумерация, годы, идентификаторы, даты и диапазоны не суммируются.
- `uReportFooter.TReportFooter` — отдельный нижний контрол отчётов, вне строк
  `gridReport`. Он рисует подпись и суммы, используя физические координаты
  логических колонок через CellRect; инвалидируется при сортировке, изменении
  раскладки/ширины и горизонтальной прокрутке. Его строки не попадают в сортировку
  или нумерацию таблицы. При смене условий подвал очищается, при новом отчёте
  пересчитывается; виден только при наличии суммируемых колонок.
- CSV создаётся из копии исходных строк с одной строкой сумм после данных.
  Для статистики метаданные оборачивают эту копию; исходные FReportLines и
  уникальные показатели статистики не меняются. Сумма читателей по группам
  является суммой строк, а не повторным вычислением уникальных читателей.
- `TReportService.LoansStatistics` агрегирует неудалённые `TLoan` по текущему ID
  книги или категории, с датой `IssuedAt` в полуоткрытом диапазоне календарных
  дней `[С, По + 1)`. Статус, возврат и RenewCount не увеличивают число операций.
  Удалённые книги/экземпляры/категории остаются связанными с историческими выдачами.
- Уникальные читатели считаются по положительному ReaderID внутри группы и в целом;
  разные книги — по BookID. Итоги не суммируют уникальные значения групп. Категория
  берётся текущая; отсутствующая категория формирует группу «Без категории».
  Выдачи с отсутствующей связью на экземпляр/книгу не включаются, число пропусков
  явно показывается на экране и в CSV. Полные данные читателей в отчёт не попадают.
- Вид отчёта имеет индекс 9 (существующие индексы сохранены), отдельные раскладки
  `.Report.9.Statistics.0/1`. Изменение условий очищает прежнюю таблицу и экспорт.
  `uGridSorting` узнаёт числовые поля «Выдач», «Книг», «Читателей»; схема с «Выдач»
  первоначально сортируется по этому полю убывающе. CSV добавляет метаданные периода
  и общие итоги перед обычной таблицей, сохраняя исходный порядок формирования.

## Сеть и внешние сервисы

- HTTPS выполняется через WinHTTP и системный SChannel; сторонние OpenSSL DLL не
  поставляются.
- Не использовать `fphttpclient` с `opensslsockets`: это возвращает зависимость
  от отсутствующих runtime-DLL.
- OpenRouter и GitHub Updates должны возвращать понятные ошибки и не нарушать
  локальную работу приложения.
- Ключи и реальные данные библиотеки не должны попадать в логи, документацию и Git.

## Поиск информации в книгах

- Порядок панели книг задан явно: название/автор/ISBN → инвентарный номер →
  очистка → Добавить → Действия → Удалённые → поиск по содержанию → Найти.
  При изменении ширины используется тот же порядок, а не текущие координаты
  перенесённых элементов. Tab соответствует порядку фокусируемых элементов.
- `uBookSearch` формирует снимок локального отбора с описаниями/категориями/
  экземплярами; модель и ключ берутся из существующих настроек OpenRouter.
  Все заполненные обычные поля объединяются по «И». Один запрос передаёт весь
  снимок; скрытого сокращения, пакетной обработки и повторов нет.
- Рабочий поток использует только снимок и копии настроек, без обращения к UI/БД.
  Таймаут сетевых операций — 60 секунд; отмена запрещает применение результата
  и ждёт возврата сетевого вызова. Повторный запуск заблокирован до завершения.
- ID результата должны принадлежать снимку и быть уникальными, ответ — завершённым
  JSON. Указание места в книге должно входить в дословную цитату из её описания;
  иначе показывается «место не установлено». Запросы, каталог и ответы не логируются.
- Активная подборка хранится в памяти. Изменение условий/обновление данных сбрасывает
  её без сетевого вызова. Обычный каталог использует прежнюю раскладку Books,
  подборка — BooksAISearch; строки содержат объекты локальных книг.
- `uBookSearchHistory` сохраняет каждый успешный запуск (включая нулевой) отдельно
  для пользователя в `Data/BookSearchHistory-<ID>.json`, версия 1. Сохраняются запрос,
  фильтры, модель, дата, проверенные результаты и MD5 содержимого локального отбора
  без даты выгрузки, с признаком удаления книг. Полный каталог, исходный сетевой
  ответ и ключи не сохраняются. История входит в полную резервную копию вместе с Data.
- Выбор истории восстанавливает фильтры и результаты без API и без смены модели.
  Изменение отпечатка помечает устаревшие сведения; недоступные книги пропускаются,
  исходные ранги сохраняются. Автоматического удаления записей нет. Явная очистка
  с подтверждением затрагивает только текущего пользователя. Ошибка чтения блокирует
  новые записи до явной очистки, сохраняя исходный файл.
- `uJSONFile` использует `TSafeIO` с проверкой JSON и атомарной заменой без журналирования
  содержимого. Формат бинарных файлов базы не меняется.
- `uButtonShortcuts` поддерживает кнопки и пункты меню с областью действия:
  проверяет активную вкладку, доступность, родительские меню и защищает ввод текста.

## Модели и цены OpenRouter

- Диалог выбора создаётся и наполняется через `CreateModelSelectionForm` без сети
  и показа. Обработчик выбора таблицы подключается после создания кнопок и защищён
  на время инициализации/уничтожения: настройка горячих клавиш может запросить Canvas,
  создать handle формы/таблицы и вызвать события выбора уже внутри конструктора.
- `uTwoLineCombo` задаёт отдельную однострочную высоту редактируемой части и
  двухстрочную высоту пунктов через LM_MEASUREITEM, включая пересоздание Win32 handle
  после смены шрифта. Применяется к выбору модели и истории информационного поиска.
- `uOpenRouterModels` добавляет три рекомендуемые модели в список настроек, сохраняя
  избранное и выбранный ID. Отрисовка показывает цену, но значения Items/Text остаются
  исходными ID для API и Settings.dat. Закреплённые модели не теряются при лимите диалога.
- Публичный `/api/v1/models` доступен без ключа. Полный каталог и цены кэшируются
  в `Cache/OpenRouterModels.json` (версия 1) с датой загрузки; цены пересчитываются
  из USD/токен в USD/1 млн входных и выходных токенов. Отсутствующая цена — неизвестна,
  явный ноль — бесплатно. Кэш не входит в резервную копию.
- Загрузка выполняется рабочим потоком, таймаут 15 секунд; при ошибке используется
  кэш с прежней датой. Первое раскрытие списка за сеанс и кнопка «…» обновляют цены;
  отмена не применяет загруженные данные к форме.

## Заполнение по ISBN

- Согласованное правило: РГБ первая, затем Open Library и Google Books;
  после успеха не дополнять поля из других источников. OpenRouter здесь не использовать.
- `uRsl` разбирает только библиографические поля; `uBookText` выполняет
  локальную очистку и предупреждения; `uOpenLibrary` координирует источники и кэш.
- `uBookHttp` сохраняет cookies одной сессии и ограничивает ожидание всех запросов
  источника 15 секундами. При таймауте сетевой поток завершает запрос самостоятельно,
  не обращаясь к UI, кэшу или базе. Следующий источник получает отдельную сессию.
- Форма применяет только отмеченные поля после просмотра. Кэш используется в конце
  цепочки и повторно проверяется; исходный источник отделён от признака офлайн-загрузки.
- Внутренний интерфейс РГБ не гарантирует стабильность; неподходящий формат ответа
  приводит к предупреждению и переходу к резервному источнику.

## Обновление приложения

- Клиент читает только последний опубликованный стабильный GitHub Release.
- Версии сравниваются как `major.minor.patch`; тег может иметь префикс `v`.
- Ожидается архив `Library-v<версия>-win64.zip` с GitHub digest
  `sha256:<хеш>` и файлами `Library.exe`, `LibraryUpdater.exe`, `INSTALL.md`.
- До установки проверяются размер, SHA-256 и состав архива, затем создаётся
  резервная копия данных.
- Updater ждёт завершения приложения, сохраняет предыдущий EXE как
  `Library.exe.old`, заменяет файл, перезапускает программу и выполняет откат
  при ошибке.
- Перенос нового EXE разрешён между дисками (TEMP и приложение могут находиться
  на разных томах). Системный код ошибки сохраняется сразу после вызова Windows;
  сообщение об успешном откате выводится только после восстановления EXE.
- `Data`, `Covers`, `Backup` и `Logs` updater не изменяет.
