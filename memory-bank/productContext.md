# Контекст продукта

## Зачем нужна система

Библиотекарю и администратору храма нужен простой локальный учёт фонда и выдач,
который не требует сервера или внешней СУБД. Интернет не нужен для основной
работы с каталогом и данными.

## Основные сценарии

1. Пользователь входит по логину и паролю.
2. Ведёт каталог книг и экземпляров с инвентарными номерами.
3. Регистрирует читателей, выдаёт, возвращает и продлевает книги.
4. Видит просрочки, отчёты и журнал действий.
5. Администратор управляет пользователями, настройками и резервными копиями.
6. Администратор вручную проверяет стабильные обновления на вкладке «Настройки».

## Сетевые возможности

- GitHub используется только при ручной проверке и загрузке обновления.
- OpenRouter используется только для явно вызванных функций распознавания и
  проверки модели.
- Ошибка или отсутствие сети не должны мешать локальной библиотечной работе.

## UX-цели

- Понятные русские сообщения об ошибках и состоянии длительных операций.
- Подтверждение удаления, восстановления и установки обновления.
- Скрытие логически удалённых записей в обычном режиме.
- Отображение текущей версии в заголовке и на вкладке «Настройки».
- Перед обновлением — проверка целостности и автоматическая резервная копия.
