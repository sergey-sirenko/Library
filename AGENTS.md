# Руководство по репозиторию

## Структура проекта и модулей

Это настольное Windows-приложение учёта библиотеки храма на Free Pascal и Lazarus. `LibraApp.lpr` — точка входа, `Library.lpi` — файл проекта Lazarus. Основные модули находятся в `src/`: `uTypes.pas` содержит общие типы и константы, `uDatabase.pas` отвечает за хранение данных, остальные `u*.pas` — за инфраструктуру, индексы, отчёты и UI-помощники. Формы лежат в `src/forms/`; визуальная форма обычно имеет пару файлов `.pas` и `.lfm`. Исполняемый файл и рабочие данные находятся в `Prog/`, результаты компиляции — в `lib/`. Не вносите изменения в `Prog/Data`, `Prog/Logs`, `Prog/Backup` и `lib/`.

## Сборка, проверка и разработка

Откройте `Library.lpi` в Lazarus 3.x/4.x и выберите **Run → Build**. Сборка из PowerShell:

```powershell
lazbuild Library.lpi
```

Результат — `Prog/Library.exe`. Собирайте проект после каждого изменения исходного кода или формы; если приложение запущено, закройте его перед сборкой. Автоматических тестов пока нет, поэтому вручную проверяйте затронутый сценарий: вход, каталог, выдачу, отчёты или резервное копирование.

## Стиль кода и именование

Используйте Object Pascal в режиме `{$mode objfpc}{$H+}`. Соблюдайте существующий стиль: отступ в два пробела, `begin`/`end` на отдельных строках и ранний выход при ошибках. Имена модулей начинаются с `u` и используют PascalCase (`uSafeIO.pas`, `uMainForm.pas`); типы начинаются с `T`, константы пишутся в `UPPER_SNAKE_CASE`, а параметры и локальные переменные при принятом в модуле подходе — с `A` (`AStatus`, `ALibraryName`). Тексты интерфейса и документация — на русском.

Сохраняйте данные через существующие уровни бинарного ввода-вывода и безопасной записи. Не меняйте формат `.dat`/`.idx` без необходимости. Удаление логическое, связи сущностей строятся по внутренним ID.

## Коммиты и pull request

В этой копии нет метаданных Git, поэтому локальный стиль сообщений коммитов определить нельзя. Используйте короткие сообщения в повелительной форме, например `Исправить проверку продления выдачи`. Один коммит должен решать одну задачу. В pull request укажите видимое пользователю изменение, риск для данных или миграции, результаты ручной проверки, ссылку на задачу при наличии и снимки экрана при изменении форм или вёрстки.

## Безопасность и конфигурация

Не добавляйте в коммиты реальные данные библиотеки, журналы, резервные копии, пароли и API-ключи. Учётные данные `admin`/`admin` предназначены только для первоначального входа и должны быть изменены при развёртывании.
