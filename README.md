# Библиотека храма

Настольная информационная система учёта библиотеки храма на Free Pascal / Lazarus.

Текущая версия: **1.1.0**.

## Требования

- Lazarus 3.x / 4.x с Free Pascal (только стандартные пакеты LCL / LazUtils / FCL / RTL)
- Windows

## Сборка

1. Откройте `Library.lpi` в Lazarus.
2. Меню **Run → Build** или:

```bat
lazbuild Library.lpi
```

3. Запустите `Library.exe`.

Точка входа: `LibraApp.lpr` (имя `Library` нельзя использовать как идентификатор программы — это ключевое слово Pascal).

## Первый вход

- Логин: `admin`
- Пароль: `admin`

Сразу смените пароль администратора.

## Обновление программы

Администратор может открыть вкладку **«Настройки»** и нажать
**«Проверить обновление»**. Программа проверяет последний стабильный релиз GitHub.
Если доступна новая версия, приложение:

1. скачивает архив и проверяет его размер и SHA-256;
2. проверяет состав архива и создаёт резервную копию данных;
3. закрывается, заменяет `Library.exe` через `LibraryUpdater.exe` и запускается снова.

Папки `Data`, `Covers`, `Backup` и `Logs` при обновлении не заменяются. Предыдущий
исполняемый файл сохраняется рядом под именем `Library.exe.old`.

Версию `1.1.0` пользователям предыдущих сборок нужно установить вручную; начиная
с неё дальнейшие обновления доступны из программы.

## Выпуск новой версии

1. Измените `APP_VERSION` в `src/uTypes.pas` и зафиксируйте все изменения.
2. Запустите `scripts\Build-Release.ps1`. Скрипт требует чистую рабочую копию,
   собирает оба EXE, запускает тесты и создаёт в `dist` архив
   `Library-v<версия>-win64.zip` и файл `.sha256`.
3. Создайте стабильный GitHub Release с тегом `v<версия>` и приложите оба файла.
   Имя ZIP изменять нельзя: по нему приложение находит пакет обновления.

Черновики и предварительные релизы приложением игнорируются. Архивы релизов не
нужно коммитить в ветку репозитория.

## Возможности

- Каталог книг и экземпляров с уникальными инвентарными номерами
- Читатели, выдача / возврат / продление
- Просрочки, отчёты (экран + CSV)
- Категории, пользователи и роли
- Логическое удаление, журнал действий
- Собственные бинарные `.dat` и индексы `.idx`
- Безопасная запись и резервное копирование

## Структура данных

```
Library\
├── Library.exe
├── Data\          — бинарные .dat и индексы .idx
├── Covers\        — обложки книг
├── Backup\        — резервные копии
└── Logs\          — журнал действий и технический журнал
```

Каталоги создаются автоматически при первом запуске.
